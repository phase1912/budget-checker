## Findings

1. **LOW — `backend/app/routers/receipts.py:61-67` — `_check_amount` admits `Decimal('Infinity')` and mishandles NaN.** *(This finding is the attempt-1 finding corrected per gate_finding#224.)* `if amount < 0:` (line 61) refuses `-Infinity` and raises `InvalidOperation` on NaN — the latter surfacing as an unhandled 500 rather than the 422 RCR-7 specifies. **Positive** infinity passes both checks: `Decimal('Infinity') < 0` is False, and `amount.as_tuple().exponent` is the string `'F'`, so line 67's `isinstance(exponent, int)` guard skips the precision check and the value reaches `Receipt(amount=...)` (line 114). On sqlite it stores a garbage amount silently; on the deployed Numeric(12,2) database it becomes a database error under `register_error_handling`. The requirements never decided non-finite amounts (baseline open question 5 covers only finite upper bounds), so this is a decided-gap rather than a requirement violation; a `not amount.is_finite()` guard at the top of `_check_amount` would close it. **This is about the code, not this document — a `code_change` artifact, for the person to send back or wave through as a deliberate undecided edge.**
2. **LOW — `backend/tests/test_receipts_crud.py:109,120` — the attempt-2 fix has never been executed.** The `_naive_utc_now()` comparison (lines 97–101, 109) and `.replace(tzinfo=None)` normalization (line 120) were written after the only suite run on record — the implementation stage's own gate, whose run is recorded in gate_finding#171 as 1 failed / 76 passed on the pre-fix tree (a figure attributed to that record; this stage did not reproduce it). The root cause quoted in code_change#170 is sound against the code I read (models.py `_now` returns aware UTC; sqlite stores naive), and the fix is confined to that test's arithmetic. Not a code defect; it is residual risk, not a `code_change` finding, because no stage of this run — including this one — runs a shell.
3. **LOW (test hygiene) — `backend/tests/test_receipts_crud.py:178` — `assert body["created_at"][:2] == "20"` is a string-prefix year check.** It would pass for any century beginning "20"; the meaningful assertion (the client-supplied id was ignored) is line 177. Cosmetic.
